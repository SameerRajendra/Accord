Engineering case study

Accord: a negotiation-intelligence pipeline, measured rather than claimed

A self-hosted LLM system that reads a negotiation transcript and returns per-turn escalation, extreme-behaviour flags, retrieved precedent, and a grounded recommendation. Served on a rented H100 that scales to zero. This page reports what was measured, what wasn't, and the three things that went wrong badly enough to be worth writing down.

Qwen2.5-7B-Instruct · SGLang · Modal H100 LangGraph · FastMCP · pgvector on Neon Corpus: CaSiNo, 1,030 dialogues

The shape is the point: continuous batching converts idle GPU into throughput almost linearly while p50 latency stays nearly flat to concurrency 16, then bends. Self-hosting only beats managed inference at high utilisation, and this curve is where that break-even actually sits.

The honest wart is TTFT p95. It spikes at concurrency 8, 32 and 64 — queueing as a batch fills faster than it drains. Median time-to-first-token stays fine, so reporting only p50 would have hidden it. It's in the table because leaving it out would make the curve look cleaner than the system is.

Why scale-to-zero

An always-on H100 is roughly $1,500/month. This idles at $0 and costs about $0.003–0.012 per warm request. The price is a ~98-second cold start on the first hit, documented rather than hidden.

Why one model, not two

A single 7B instruct model serves classification and recommendation. The small+large tier is a real design in the doc, but it isn't deployed — so it's written as future work, not as architecture.

Why XGBoost sits in an LLM pipeline

Breakdown risk wants a calibrated probability in milliseconds, not a generated sentence. It is deliberately the one non-LLM component — and the one that produced the clearest negative result.

What it actually returns

Live output

Verbatim from the deployed endpoint, on a transcript where two campers both need firewood and one issues an ultimatum. The model receives turn text only — no labels, no scenario name.

Alongside it, the behaviour detector flagged exactly two of six categories — ultimatums on turn 3 and personal_attacks on turn 2 — each with the quoted span that triggered it, and the other four correctly false. Structured output is guaranteed at the serving layer by grammar-constrained decoding, so there is no JSON-repair loop anywhere in the codebase.

Three things that went wrong

Documented

The most useful part of the project. Each of these changed a design decision, and two of them are findings rather than bugs.

01 RAG fabricated a citation while appearing to be grounded

The recommendation cited a real retrieved case to justify walking away: 

"...as seen in [casino-204], where a walk-away strategy
 led to an agreement that balanced both parties' needs."

The retrieved case contains no walk-away. It is an uneventful 18–18 trade:

"Outcome: Agreement reached — agent_2 gets 0 Firewood,
 2 Water, 2 Food... Lesson: A balanced deal — both
 parties scored 18 points."

Root cause: retrieval returned five amicable agreements at cosine scores of 0.42–0.44 for a hostile-conflict query — the query is raw dialogue text while the corpus documents are structured summaries, a vocabulary mismatch. With no supporting evidence in context and a prompt that asks it to cite sources, the model cited anyway and invented the supporting detail.

Why it matters: this is the exact failure retrieval-augmentation is meant to prevent, occurring inside a citation that looks trustworthy. It is reproducible, and it is the reason the RAG-versus-no-RAG ablation is the project's headline experiment rather than a formality.

02 The prediction target was near-degenerate, and the metrics hid it

The breakdown-risk model scored 97.1% accuracy. Impressive until you compute the majority-class baseline on the same split: 96.1%.

ModelAccuracyF1Breakdowns caught
Always predict "deal"96.1%0.9800 of 4
XGBoost97.1%0.9851 of 4

The entire gain is one dialogue out of 102. The isotonic calibrator collapsed to near-constant output — 100 of 102 predictions in a single bin at 0.99 — so the calibration claim in the design doc is unsupported on this target.

Root cause: the corpus is a cooperative task where 97.6% of negotiations succeed. Predicting a 2.4% event from 25 examples isn't a modelling problem, it's the wrong question for this data.

What changed: the eval harness now reports base rate, accuracy lift and minority-class recall next to accuracy, and the result CSV was deliberately not committed — publishing a degenerate artifact would be the exact overclaim the project exists to avoid. The target is being reframed onto an outcome with real variance.

03 The dataset's only host died mid-project

CraigslistBargain is distributed from a single CodaLab worksheet. It began returning HTTP 500 permanently — and the HuggingFace mirror turned out to be a loading script that proxies the same dead endpoint, so it failed identically.

What saved it: the schema was source-agnostic by design. Swapping corpora meant writing one ingestion script, not rebuilding a pipeline. The project re-based onto CaSiNo — which turned out to fit better anyway, carrying persuasion-strategy annotations, personality profiles and per-party outcome scores that the previous corpus lacked.

What it cost: a rewrite of feature engineering, the case-corpus builder and three test modules. What it taught: "available today" is not a dataset property you can rely on, and the abstraction that felt like over-engineering in week one is what made week four survivable.

Decisions worth defending

DecisionChosen overBecause
Serverless GPU Always-on rental $0 idle versus ~$1,500/mo, for a demo nobody hits at 3am. Cost: a 98s cold start.
Self-hosted weights Managed inference API The serving numbers above are only obtainable if you own the serving layer.
Managed Postgres Self-hosted pgvector One connection string beats a container that dies with each scheduler allocation.
Agent calls tools directly Agent as MCP client of itself Two thin adapters over one implementation, avoiding a self-network-hop.
Order-invariant features Per-party columns Which negotiator is labelled "agent_1" is arbitrary; per-party columns learn that artifact.
Strategy labels excluded Using all annotations Only 38% of dialogues carry them, so their presence encodes a selection boundary.
